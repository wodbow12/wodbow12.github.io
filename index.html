LLM이 추천 순위를 실제 씬 번호로 반환하는 오류를 발견했습니다. 씬 식별자 검증과 교정 재요청, 실패 시 규칙 기반 선택으로 전환하는 경로를 구성했습니다. JSON 형식이 맞더라도 잘못된 장면이 후속 생성에 전달되지 않도록 검증 범위를 넓혔습니다.

Tool 계약과 실행 범위 제어

견적 요약, 씬 개요, 일정 지표, 인력 부하, ShotGrid 견적, 유사 사례 검색 6개 조회 Tool을 순수 데이터 함수로 구현하고, 모든 Tool이 tool·available·summary·metrics·source·reason 6개 필드의 같은 계약을 반환하도록 레지스트리에 등록했습니다. LLM에는 600자 이내 집계 요약만 주입해 근거 수치만 쓰게 하고 응답에 출처 배지를 붙였습니다. 씬 선택, 캐릭터 생성·수정, 컨셉 재생성, 트레일러 출력 등 실행 Action 31개는 현재 작업 단계(탭)에 속한 것만 발화하며, 기존 API 엔드포인트를 경유해 중복 실행·동시성·멱등성 가드를 재사용합니다. HTTP 30초·WebSocket 600초의 타임아웃 계층을 두고, 초과 시 prompt_id를 돌려줘 get_job으로 이어받게 했습니다. 연결이 끊기면 /history를 조회해 이미 끝난 작업이 실패로 보고되지 않도록 했습니다.

결과와 오류 — 에이전트가 다음 행동을 고를 수 있는 형태

1024² PNG는 1~2MB라 컨텍스트를 낭비하므로 긴 변 512px 썸네일을 image 콘텐츠로, 원본은 경로와 seed 텍스트로 분리해 반환합니다. 실패는 예외 대신 isError와 읽을 수 있는 원인(모델 파일 없음, VRAM 부족, 검증 실패 노드·필드)으로 돌려줘 에이전트가 파라미터를 바꿔 재시도할 수 있게 했습니다. 의존 라이브러리의 stdout 출력이 프로토콜을 깨뜨리지 않도록 기동 직후 stdout을 stderr로 리다이렉트했습니다.

단위·프로토콜·실제 클라이언트의 세 층으로 검증했습니다.

pytest로 WorkflowTemplate.render()의 노드 치환, step 정렬과 범위 클램프, 잘못된 target에서의 기동 실패를 확인했습니다. websockets 목 서버로 status → executing → progress ×N → executed → executing(null) 시퀀스를 재생해 진행률 콜백 횟수와 최종 이미지 수집, execution_error 분기를 검증했습니다.

매핑 단위 테스트→WS 이벤트 재생→MCP Inspector→Claude Desktop · Code→OOM 재시도 흐름

2048px 요청이 GPU 메모리 부족으로 실패했을 때 힌트대로 1024px로 재시도해 성공하는 흐름을 확인했습니다. 테스트 중 연결이 정상 종료될 때 미완료 작업을 "완료"로 보고하던 결함을 발견해 수정했습니다. 성공률·절감 비율 같은 집계 수치는 측정 범위를 제한해 기재하지 않았습니다.

검증 과정

MCP Inspector로 tools/list 스키마, tool 호출, progress notification 수신, resource 읽기를 확인한 뒤 Claude Desktop과 Claude Code에 서버를 등록해 "고양이 사진 1장 만들어줘" 같은 자연어로 end-to-end 생성과, 실패 메시지를 보고 스스로 재시도하는지를 확인했습니다. GPU가 없는 환경에서도 API 호환 mock ComfyUI로 같은 절차를 재현할 수 있게 했습니다.
